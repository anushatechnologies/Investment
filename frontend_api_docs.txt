3. WHATSAPP STATUS ENUM VALUES & RECOMMENDED FRONTEND UI LOGIC
--------------------------------------------------------------------------------
- NOT_SENT  : Dispatch not initiated. (Show default receipt UI)
- QUEUED    : Queued in background worker. (Display: ⏳ Preparing receipt... | Keep polling every 2-4s)
- SENDING   : Payload sent to Meta API. (Display: ⏳ Sending to WhatsApp... | Keep polling)
- SENT      : Dispatched by Meta to user. (Display: ✓ Sent to WhatsApp)
- DELIVERED : Received by user's WhatsApp. (Display: ✓✓ Delivered to WhatsApp)
- READ      : Opened by user on WhatsApp. (Display: ✓✓ Read on WhatsApp)
- FAILED    : Delivery failed (invalid number / blocked). (Display: ⚠ Delivery failed | Download PDF remains active)


4. META WHATSAPP WEBHOOK ENDPOINTS (AUTOMATED SERVER-TO-SERVER)
--------------------------------------------------------------------------------
Verification Endpoint: GET https://api.anushatrade.com/api/webhooks/whatsapp
Query Parameters:
  - hub.mode = subscribe
  - hub.verify_token = anusha_whatsapp_verify_token
  - hub.challenge = <challenge_string>
Response: 200 OK with challenge string

Event Endpoint: POST https://api.anushatrade.com/api/webhooks/whatsapp
Content-Type: application/json
Payload: Meta WhatsApp Cloud API status notification payload (sent, delivered, read, failed).
Response: 200 OK ("EVENT_RECEIVED")


5. SECURITY & ACCESS CONTROL
--------------------------------------------------------------------------------
1. All client endpoints (/api/receipts/**, /api/payments/**) require Bearer JWT token in Authorization header.
2. Authenticated user can only query receipts for investments owned by their account.
3. Webhook endpoints (/api/webhooks/whatsapp) are publicly accessible for Meta Cloud API integration.
